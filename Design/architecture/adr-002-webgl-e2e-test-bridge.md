# ADR-002: Development WebGL E2E test bridge

상태: 승인됨
일자: 2026-09-07

## 결정

실제 WebGL 실행을 검증하기 위해 Development WebGL 빌드에만 브라우저 테스트 브리지를 둔다. 브리지는 `window.AftertasteE2E`에 구조화된 이벤트 버퍼를 제공하고, Unity 쪽에는 `AftertasteE2ETestBridge`라는 수신 지점을 둔다.

릴리스 빌드에는 브리지 코드, 브라우저 전역 객체, 테스트 명령이 포함되지 않는다.

## 경계

- 브리지가 제공하는 것: 부팅·씬 전환·오류·명시적 마커의 구조화 로그, 상태 스냅샷 요청, 테스트 중 시간 배율 변경.
- 브리지가 제공하지 않는 것: 플레이어 이동, UI 클릭, 미니게임 성공, 게임 규칙 우회.
- 여정의 이동·클릭·선택·미니게임은 브라우저의 실제 키보드·마우스 입력으로 실행한다.
- 긴 준비나 드문 상태 재현은 기존 개발 명령/Scenario로 보조할 수 있으며, 결과 보고서에 실제 입력 단계와 설정 단계를 구분한다.
- 매 E2E 실행은 별도 포트(origin)를 사용한다. 따라서 브라우저 저장소가 일반 플레이와 공유되지 않는다.

## 검증 산출물

각 시나리오는 화면 캡처, `AftertasteE2E.events` JSON, 브라우저 콘솔 오류, 실행 시간을 남긴다. 통과 조건은 화면만이 아니라 예상 상태 스냅샷과 실제 입력 후의 상태 변화를 함께 만족하는 것이다.

## 대안과 이유

Unity 내부 시뮬레이션만으로는 WebGL 입력 매핑, Canvas 좌표, 브라우저 저장소, 실제 표시 문제를 잡을 수 없다. 반대로 모든 준비를 실제 조작으로만 하면 긴 게임 진행 때문에 회귀 검증이 비현실적으로 느려진다. 그래서 관측과 준비는 개발 전용 브리지, 사용자 여정의 핵심은 실제 브라우저 입력으로 나눈다.

## 되돌리기

이 ADR과 `AftertasteE2ETestBridge`, WebGL 플러그인, 빌드 후처리기를 제거하면 기존 Development/Release 빌드 동작으로 돌아간다. 저장 포맷과 게임 런타임 상태에는 변경이 없다.
